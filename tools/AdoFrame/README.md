# AdoFrame

ADOFIA 二创性能采集工具。选择任意窗口，采集帧率、帧时间、1% Low、内存、CPU 等指标，结束后导出 CSV / HTML 报告，用于组内作品横向对比。

- **UI**：C# / .NET 8 WinForms，深色主题，自绘实时曲线
- **窗口采集**：Windows Graphics Capture（WGC）
- **原生游戏采集**：Intel PresentMon 2.6.0（随包附带，MIT）
- **不依赖 Python / 浏览器 / 前端运行时**

## 功能

- **任意窗口**：任何可见的桌面窗口都可以作为目标，不要求是游戏进程。
- **浏览器标签页**：浏览器 / Electron 窗口自动使用窗口级 WGC 采集。帧率、帧时间、1% Low 只统计**目标窗口当前活动的标签页**，不会把同一浏览器的其它窗口混进来。
- **原生游戏**：自动模式对非浏览器窗口使用 PresentMon 进程级采集，支持高于显示器刷新率的 Present 帧。
- **自动回退**：PresentMon 6 秒内没有捕获到帧时，会自动切换为窗口捕获。
- **实时显示**：FPS、1% Low、0.1% Low、帧时间 / P99、内存、CPU、运行日志、帧时间曲线。
- **最终统计**：平均 FPS、1% Low、0.1% Low、P50/P95/P99 帧时间、最大帧时间、CPU 均值/峰值、工作集/私有内存峰值、内存增长、线程/句柄、前台采样占比等。
- **一键导出**：汇总 CSV、每秒时间线 CSV、原始帧 CSV、JSON、自包含 HTML 报告，并自动追加一行到 `汇总.csv`。
- **全局停止热键**：**默认关闭**，需要时可在设置里启用 `Ctrl+Alt+F9` 等组合；不注册 F5/F12 等浏览器常用键。

## 运行要求

- Windows 10 2004（build 19041）或更高版本，64 位
- 窗口捕获需要 WGC；Windows 11 上默认关闭黄色捕获边框
- 使用 PresentMon 采集高权限 / 受保护进程时，建议以管理员身份运行 AdoFrame
- 自己构建：.NET 8 SDK；发布自包含版本后目标机不需要安装 .NET

## 快速使用

1. 启动 AdoFrame。
2. 在左侧列表选择目标窗口，或点击“拾取窗口”后直接点击目标。
3. 选择采集方式（一般保持“自动”）。
4. 设置采集时长（0 = 手动停止）、预热、帧时间上限、开始倒计时。
5. 点击“开始采集”（窗口内 `F9`）。
6. 采集结束后自动导出到输出目录；也可以在右侧手动点击“导出 CSV / 导出 HTML”。

### 浏览器 / Electron 注意事项

Windows 没有暴露“标签页”句柄，所以浏览器标签页无法像独立窗口一样单独捕获。AdoFrame 的做法是：

- **帧率 / 帧时间 / 1% Low**：WGC 捕获所选浏览器窗口的 DWM 呈现，因此反映的是**当前活动标签页**的画面；同一浏览器的其它窗口不会混入。
- **内存 / CPU**：只能统计窗口所属的进程树。对浏览器来说，这会包含同一浏览器实例的其它标签页、渲染进程和 GPU 进程，无法做到严格的单标签页内存隔离。
- 采集中请保持目标标签页活动、窗口可见；不要最小化窗口。切换到另一个标签页会改变被采样的画面，日志会提示窗口标题变化。
- 如果浏览器把后台标签页节流，后台期间的帧率没有参考意义；请让目标窗口保持前台。

### 原生游戏注意事项

- 游戏使用独占全屏时，WGC 可能无法捕获；请使用 PresentMon，或改成无边框全屏 / 窗口模式。
- PresentMon 按**进程**采集，会收集该进程的所有交换链；AdoFrame 会自动选择最活跃的交换链，其它交换链的原始帧仍会保留在 `frames.csv` 中。
- 如果游戏有启动器、覆盖层或多个窗口，进程级数据可能包含它们；需要严格窗口级数据时请选“窗口捕获”。

## 指标口径

| 指标 | 计算方式 |
| --- | --- |
| 平均 FPS | `1000 / 有效帧间隔的平均值`（调和平均口径） |
| 1% Low FPS | 取最慢 1% 帧的帧时间平均值，再换算为 `1000 / 平均帧时间` |
| 0.1% Low FPS | 取最慢 0.1% 帧的帧时间平均值，再换算为 FPS |
| P99 帧时间 | 有效帧时间的第 99 百分位（线性插值） |
| 有效帧 | 预热结束后、且帧时间不超过“帧时间上限”的帧；所有汇总指标都只用这部分数据 |
| 工作集 | 窗口所属进程树所有进程 `WorkingSet64` 之和；浏览器包含整个浏览器进程树 |
| 私有内存 | 进程树 `PrivateMemorySize64` 之和（提交的私有内存） |
| CPU% | 进程树 CPU 时间增量 / 实际经过时间 / 逻辑处理器数，即整机占用百分比 |
| 前台占比 | 每秒采样时目标进程是否拥有前台窗口 |
| GPU 忙碌 | 仅 PresentMon 提供：按帧 `MsGPUBusy` 汇总估算，WGC 模式为 N/A |

> 所有汇总指标（含内存峰值、CPU 峰值）都排除预热区间和超过“帧时间上限”的帧。`frames.csv` / `timeline.csv` 仍保留预热数据用于追溯，`timeline.csv` 的 `warmup` 列和 HTML 图上的黄色阴影会标出预热区间。
>
> WGC 受显示器刷新率上限约束，统计的是“窗口实际呈现节奏”；PresentMon 统计的是进程 Present 帧，可以高于刷新率。两者不要直接混用比较。

## 快捷键

| 按键 | 作用域 | 说明 |
| --- | --- | --- |
| `F5` | 仅 AdoFrame 窗口内 | 刷新窗口列表 |
| `F9` | 仅 AdoFrame 窗口内 | 开始 / 停止采集 |
| `Esc` | 仅 AdoFrame 窗口内 | 取消倒计时 / 窗口拾取 |
| `Ctrl+Alt+F9`（可选） | 全局 | 只停止采集，不会开始；需在设置中手动启用 |

- **默认不注册任何全局热键**，因此浏览器、游戏收到的按键与正常情况完全一致。
- 启用后使用 Win32 `RegisterHotKey`，**不安装键盘钩子**，只占用你选择的那个组合，不会拦截 `F5`、`F12`、`Ctrl+W` 等浏览器快捷键。
- 全局热键被其它软件占用时，注册会失败并在运行日志 / 热键设置下方提示；窗口内的 `F9` 仍然可用。
- 如果不想让 AdoFrame 接收任何全局按键，保持“关闭（仅窗口内 F9）”即可。

## 输出文件

每次采集会在输出目录下生成一个会话文件夹：

```
20261017_185139_AnimWin_WGC/
├── summary.csv      # 单次采集的键值汇总，适合人工查看
├── timeline.csv     # 每秒 FPS / 帧时间 / 内存 / CPU
├── frames.csv       # 原始帧数据（可能较大）
├── session.json     # 元数据 + 汇总 + 时间线，便于后续自动化
└── report.html      # 自包含 HTML 报告，可直接发给组员
```

同目录下还有 `汇总.csv`：每完成一次采集追加一行，适合把多个人的作品汇总到 Excel。

## 构建

```powershell
cd tools\AdoFrame
dotnet build -c Release
```

开发运行：

```powershell
dotnet run -c Debug
```

发布自包含单文件（推荐分发给组员，目标机不需要 .NET）：

```powershell
.\build.ps1
```

输出在 `tools\AdoFrame\publish\`。`PresentMon.exe` 会随 `third_party\PresentMon\` 一起复制到发布目录，**不要只复制 AdoFrame.exe**。

只发布依赖框架的小体积版本：

```powershell
.\build.ps1 -FrameworkDependent
```

## 常见问题

**没有帧数据**

- 浏览器 / Electron：用“窗口捕获”，保持标签页活动，不要最小化窗口。
- 原生游戏：用 PresentMon；独占全屏建议 PresentMon。
- 确认目标窗口确实在持续渲染画面；静态窗口不会产生新帧。

**内存 / CPU 为 0 或 N/A**

- 目标进程可能以管理员权限运行，AdoFrame 没有权限读取；请以管理员身份运行 AdoFrame。
- 浏览器统计的是整个进程树，这是预期行为；严格单标签页内存需要浏览器内部接口，目前未支持。

**有黄色捕获边框**

- Windows 11 22H2 及以上会自动尝试关闭；Windows 10 或系统策略限制下可能保留。捕获边框不会改变帧数据。

**全局热键没反应**

- 全局热键默认是关闭的；需要滚动到“采集设置”下方，把“全局停止热键”改成 `Ctrl+Alt+F9` 等组合。
- 可能被其它软件占用；查看运行日志或热键设置下方的提示，换一个组合或关闭。
- 全局热键只停止，不开始；开始请点击“开始采集”或窗口内按 `F9`。

**PresentMon 警告权限不足**

- 对受保护 / 高权限进程，建议右键 AdoFrame “以管理员身份运行”。
